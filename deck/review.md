## 高（冻结前必修）

### H1. 第 4 张“电网代理”卡片布局错乱（现场页 + deck 第 3 页）

- 现象：前 3 张卡是单列；第 4 张卡变成两列——`红线`/`立场` 并排、`峰荷 ≤120 kW` 与 `限制晚高峰放电` 各自换行，底部 `峰荷 -15%` 比前 3 张低 14px。
- 根因：`app/public/powertable.js:61` 给第 4 张卡的 class 是 `pt-agent grid`；`app/public/styles.css:255` 有一条全局 `.grid { display:grid; grid-template-columns: ... }`，把这张卡也变成了两列网格。这是实时页面的真实布局，不是截图问题。
- 修法（一行）：`app/public/powertable.css` 末尾加：

  ```css
  .pt-agent.grid { display: block; }
  ```

  或把第 4 张卡的 class 从 `grid` 改为 `agent-grid`，同步改 `.pt-agent.grid` 的 `border-top-color` 选择器；一行覆盖更快。
- 验证：四张卡等高；`.pt-line` 宽度从 102px 恢复 ~220px；第 4 张卡的 gain 与前三张同一水平线。
- 连带：修完后重截 `deck/assets/powertable_main2.png`，替换第 3 页图；当前素材里第 4 卡已经是两列。

### H2. 数字孪生四条流线旁有 4 个“—”占位符（现场页 + deck 第 3 页）

- 现象：四条流线中点的标签全是“—”（黄/绿/蓝/红各一个），节点值正常（250 kWh / 放电 300 kWh / -12% / -15%），中心“放 300”正常。
- 根因：`app/public/digitaltwin.js:25-31` 与 `:88-96` 给节点值和流线标签用了同一组 `id`（`dt-pv` / `dt-storage` / `dt-factory` / `dt-grid`）；`setRound`（`:106-109`）的 `querySelector('#dt-pv')` 只命中第一个（节点值），四个 `.dt-tag` 永远停在“—”。
- 修法（二选一）：
  - 最快：`app/public/digitaltwin.css` 加 `.dt-tag { display: none; }`，隐藏四个占位符；流线粒子和节点值保留。
  - 更干净：标签改用 `dt-tag-pv` 等唯一 id，并在 `setRound` 同步更新（时间不够不要做）。
- 连带：同样要重截 `deck/assets/powertable_main2.png`；当前 deck 素材里四个彩色短横可见。

### H3. 300 vs 350 kWh 数字冲突（现场页）

- 现象：Round 2“只放 300 kWh”、Round 3“放电 300 kWh”、数字孪生储能节点“放电 300 kWh”、中心“放 300”；但沙盘右上角标注“晚高峰 · 放电 350 kWh”。
- 判断：沙盘电池序列 `-100,-100,-100,-50` 合计 350；SOC 从 90% 降到 20%（500 kWh × 70% = 350）。**350 才是图表算出来的数**，300 是文案里的孤立值。
- 建议（改文案，不动图表）：以 350 为准，改 4 处字符串——`powertable.js:20`（Round 2）、`powertable.js:26`（Round 3）、`digitaltwin.js:9` 的 storage 与 hub；并同步 `TOPIC.md` §2.6 的“放 300 kWh”。BRIEF 和 deck 文本都没有 300/350，deck 数字不受影响；重截第 3 页图后会显示 350。
- 不推荐改成 300：要同时改沙盘电池序列、SOC 和 ¥87.5 收益，冻结前风险大。

### H4. `?pt=play` 等 8 秒后，首屏看不到 92% 共识（投屏/演示）

- 1920×1080 实测：92% 的 `strong` 从 `y=1080` 开始，正好在视口底边；首屏只看到“协议达成”标签和上半屏消息，**看不到 92% 这个数字**。5 个指标在 `y=1246`，完全在屏外。
- 1366×768 实测：数字孪生从 `y=533` 到 `947`，首屏只看到上半段；谈判区 `y=959` 以下，92% 完全看不到。
- 根因：`.masthead` 占了 150px，powertable 从 `y=262` 才开始；自动谈判在 4.1s 完成，但页面没有把结果带进视口。
- 修法（建议都做）：
  1. `?pt=play` 时给 `body` 加 `pt-demo`，CSS 隐藏 `.masthead`（省 150px）；保留 topbar 的 DEMO 徽标。
  2. `pt:done` 后执行 `document.querySelector('#pt-arena').scrollIntoView({ block:'center', behavior:'smooth' })`，只在 `?pt=play` 生效。1920 下隐藏 masthead 后 92% 已可见；1366 下必须靠这步滚动，否则永远在屏外。
- 顺带：demo 模式下建议隐藏 `.stepper`，避免“01 输入”出现在沙盘之后（页面顺序是 谈判→对比→沙盘→输入→输出，步骤条却是 01 输入→02 谈判→03 确认，叙事是反的）。

### H5. deck 第 1、5 页仍有 `[待填]`（提交阻断）

- 位置：第 1 页底部“团队 [待填] 汇报人 [待填]”；第 5 页底部同样两处。
- 现状：`DECK_STATUS.md` 已列为待办，但复核时仍在；这是提交前必须清零的占位符。
- 修法：总控给团队名/汇报人；若确实不写个人名，至少把整行删掉，不要留 `[待填]`。B 改第 1、5 页后重导。

## 中

### M1. 沙盘左上角 “kW” 被 “00:00” 时间标签遮住

- 现象：`app/public/sandbox.js:131` 的 y 轴单位 `kW` 在 `x=M.left-10, y=M.top-10`；时间游标 00:00 的胶囊在 `x(0)-24 … +24, y=M.top-22 … -4`，两者在左上角重叠，截图里 `kW` 基本被盖住。
- 修法（一行）：把 `kW` 移到绘图区右上角：

  ```js
  txt(svg, M.left + PLOT_W - 6, M.top - 10, 'kW', { 'text-anchor': 'end', fill: '#66707f' });
  ```

  或下移到 `M.top + 30`；不要留在 00:00 胶囊的占用区。
- 验证：初始 00:00 与播放到 24:00 都不重叠。

### M2. 1920 投屏下内容只占 1068/1920，正文 11–13px

- 实测：`.shell` max-width 1180 + padding 56 → 暗色卡片宽 1068px，1920 屏左右各空 419px；`.pt-line` 11px、`.pt-msg p` 12px、`.cmp-ai` 13px、`.sb-legend` 13px。3 米外投影偏小。
- 修法（按代价排序）：
  1. 演示前把浏览器缩放到 125%（Ctrl+加号）作为兜底；配合 H4 隐藏 masthead，减少滚动。
  2. 若要改代码：给 `?pt=play` 加演示样式，`.shell { max-width: 1500px; }`，并把关键正文提高 2–3px（`.pt-line` 13px、`.pt-msg p` 14px、`.cmp-ai/.cmp-human` 14px、`.cmp-label` 12px、`.sb-legend` 14px）；只放宽 shell 不放大字号没用。
- 注意：改字号会让页面更高，必须与 H4 的隐藏 masthead/自动滚动一起做，否则首屏更糟。

### M3. deck 第 3 页主视觉 UI 截图约 4pt，投屏读不清

- 实测：第 3 页图片放在 4.86in 宽，源图 1080px；UI 正文 11–12px → 在幻灯片上约 4pt（1600×900 导出约 6.5px）。即使修好 H1/H2，观众也读不到卡内文字和聊天气泡。
- 修法：
  - 不要把整张 UI 当信息载体；右侧 01/02/03 已承担文字信息。
  - 最快：在图上叠 3 个大数字标注（`弃光 250→0`、`峰荷 -15%`、`共识 92%`），字号 24–28pt；截图退为背景。
  - 若重排版：只裁“四代理卡 + 92% 共识”两栏，或裁“92% + 4/4”单块放大；整张 4 卡截图无论怎么放大，文字宽度比不变，仍然只有 ~4–5pt。
- 时间不够时至少做前者；不要花时间重画整页。

### M4. deck 第 4 页对比表 9–9.5pt，后排偏小

- 现状：表格 7 行 + 表头，9–9.5pt；1600×900 导出约 15–16px。Qwen 复核“可读但勉强”，投屏 2–3 米是下限。
- 修法：若第 3 页改完后还有时间，把表格正文提到 10pt、表头 10.5pt；优先保证 6 个核心数字（40 分钟 / 250→0 / 1.4→1.0 / -12% / 140→119 / 2/4→4/4·92%）不小于 10pt。若放不下，删掉 BRIEF 之外的“决策依据”行（该行来自 TOPIC，不是 BRIEF 必需）来换行高。
- 这是加分项，不是阻断；不要为了 1pt 导致表格越界。

## 低

### L1. 对比条 AI 18% 与“秒级”不一致

- `app/public/compare.css:87-97` 把 AI 条设为 18%（=40 分钟的 7.2 分钟），文字却是“3 轮 · 秒级”；视觉上高估了 AI 耗时。
- 修法：`.cmp.is-ai .cmp-bar.ai i { width: 4%; min-width: 6px; }`，或在条旁加“示意”二字；不要用 18% 这种可被换算的比例。

### L2. 沙盘初始停在 00:00，日净收益 ¥0.0

- `?pt=play` 只自动播放谈判，沙盘仍是 00:00 / 充电 100 kW / ¥0.0；如果截屏或观众先看到沙盘，会以为“没跑”。
- 修法：演示时先点“播放一天”到 24:00 再讲；若要截图，截 24:00（¥87.5）；或在 `?pt=play` 里延迟触发一次 `#sb-play`（沙盘在首屏下方，播放完再滚过去正好）。

### L3. deck 第 3 页储能行漏了“≤1 次循环/日”

- 第 3 页四代理列表只写“储能 · 收益与寿命 / SOC 20–90%”；BRIEF 的约束是“SOC 20–90%、储能 ≤1 次循环/日、峰荷 ≤120 kW”。第 4 页表格有 1.0 次/日，但第 3 页红线不完整。
- 修法：若该行放得下，改为“储能 · 收益与寿命 / SOC 20–90% · ≤1 次/日”；放不下就不动，口播补一句。

### L4. “日净收益”与“储能日收益”口径

- powertable 写“日收益 +87.5 元”（储能代理），沙盘写“日净收益 … 目标 +¥87.5”。如果 87.5 只是储能套利收益，建议沙盘标签改为“储能日收益”，避免被问“系统净收益怎么只有 87.5”。
- 修法：`app/public/sandbox.js:267` 的 KPI 标签 `日净收益` → `储能日收益`（一行），或在 note 注明口径。
